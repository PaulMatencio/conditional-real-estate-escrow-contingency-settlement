Before you start: How the escrow works

The buyer locks the agreed price in a shielded coin on the Midnight preview network. Inspection, financing, and title contingencies are attested, and funds go either to the seller or back to the buyer.

Privacy-First Design

  • Private on-chain: Prices, payout keys, and report documents never appear on-chain—only salted commitments and report hashes.
  • Local proving: Zero-knowledge proofs are generated on each user's computer via the local proof server.
  • Client-side vault: Secret keys, terms, attestations, and salts stay encrypted (AES-GCM) in the browser.

Two Execution Modes

  • Wallet Mode: Real escrow on the Midnight preview network—real transactions, DUST fees, and local proof server (9.0.1). No wallet? Every page still Loads the escrow read-only from the indexer; connect a wallet only to act.
  • Simulator Mode: Compiled contract running inside the browser with no wallet, no fees, and a movable clock. Use Create simulated escrow to rehearse a full deal in minutes.
Every action button checks its preconditions first; disabled buttons explain why underneath (wrong phase, deadline passed, missing key or terms).

What each person needs

Requirements for running the dApp securely in Wallet Mode (and testing multiple roles locally).

1. Browser & Secure Origin

  • Chromium or Firefox on http://localhost:3000 or http://<role>.localhost:3000.
  • No LAN IPs (e.g. 192.168.x.x): browsers disable WebCrypto vault encryption.
  • Own origin per role: use admin.localhost, buyer.localhost, seller.localhost so each role gets its own vault.

2. Vault & Role Key

  • Vault passphrase (8+ chars) to encrypt keys, terms, and attestations in IndexedDB.
  • Secret role key generated on /role-id (all roles except Notary & Compliance Officer).
  • Only the derived role id is shared; the secret key never leaves your device.

3. Wallet & Proof Server

  • Midnight wallet (Lace or 1AM) on preview with DUST for fees.
  • Buyer and seller must use separate wallet accounts (payout goes to that account's shielded key).
  • Local proof server running on 127.0.0.1:6300 (midnightntwrk/proof-server:9.0.1).

Cancelling before funding (even when immutable)

Parties can walk away before money is locked—even after the admin renounces maintenance authority. Renouncing freezes code, not rules.

When It Is Allowed

  • Buyer or Seller: while Initializing or Created (up to buyer's deposit).
  • Admin: only while Initializing.
  • Blocked once Funded: after deposit, exit only via contingency failure, withdrawal, expiry, or dispute.

What Happens

  • Status becomes Cancelled (final; lifecycle round +1).
  • No funds move (only network fee paid by caller).
  • Cannot be reopened or undone; stays on-chain as a public record.
  • To continue: Admin deploys a new escrow. Role/payout/envelope keys can be reused, but new KYC attestations are required.
Cleanup: Old vault records remain inert. Back up first, then use Erase locally (type ERASE) or Remove custodian copy.

Contract versions (v3 & v2) and loan financing

The dApp deploys v3 for new escrows while continuing to support v2 escrows.

Cash Deal vs. Loan Deal

  • v3 Cash Deal: No lender needed—the buyer's deposit automatically clears the financing contingency.
  • v2 Cash Deal: Lender attests financing (or buyer waives it).
  • Loan Deal: Buyer deposits own share; Lender deposits the loan into the same escrow (price = buyer deposit + loan).
  • Amounts & Units: Enter whole tokens (e.g. 250000.50 sEUR); dApp converts to base units using deploy-time decimals (e.g. 6).

Loan Outcomes & Statuses

  • Released: Seller receives both coins (buyer deposit + loan or top-up).
  • Refunded / Expired: Each coin returns to its depositor in separate transactions (Refund buyer, Refund top-up, Refund lender).
  • Forfeited: Loan lost + refund term OFF + no top-up by closing deadline → Seller claims buyer deposit.
  • Header Switcher: Manages multiple escrows; names & decimals stay in your vault.
  • Version detection: Each escrow keeps the version it was deployed with (shown as Contract version v3 / v2); no redeploy after a contract update. An unsupported version shows a banner with Archive.

Loan financing: Lender & Buyer top-up flows

Admin configures Loan mode, loan offer expiry, top-up window (default 7 days), total price, buyer deposit, lender payout key, and optional loan-refusal refund term.

Lender Guide (/lender)

  • Import lender package (checks 4 commitments: price, loan amount, refund term, lender payout key).
  • Fund the loan: Deposits exact committed loan amount.
  • Refuse the loan: Attaches refusal letter (hash only on-chain).
  • Withdraw loan deposit: Available after loan offer expiry if still in review (counts as refusal).
  • Refund the lender: Reclaims loan coin if deal unwinds.

Buyer Top-Up (/buyer)

  • Self-fund: While no loan or top-up is held, buyer can deposit the loan amount directly.
  • Loan refused/withdrawn + Refund term ON: Top-up window opens (ends at earlier of now + window or closing deadline). Top up, or Give up and get refunded at once.
  • Refund term OFF: Must top up before closing deadline, or escrow becomes Forfeited to seller.

Optional cooling-off period

Lets the buyer walk away for any reason for a set number of days after deposit, paying at most a committed penalty to the seller. Off by default.

Admin Setup

  • Initialize → Financing: Set Cooling-off period (days) (public; 0 = off).
  • Terms & KYC: Set private Penalty (% of price) (8th commitment; must be < deposit).
  • Parties must import terms before accepting configuration.

Buyer Withdrawal

  • Inside period: Sets Withdrawn (works even if Disputed). Refund the withdrawal pays deposit - penalty.
  • After period / no period: Sets Forfeited (seller claims full deposit).
  • Failed contingency: Always full refund via Cancel and refund (no penalty).

Seller & Notary

  • No release before end: Seller cannot release until cooling-off ends, even if contingencies clear.
  • Claim penalty: After withdrawal refund, seller claims penalty (requires valid seller KYC).
  • Notary: Verifies penalty opening & records cooling-off section on certificate.

Admin guide: 9-step setup & finalization

Run on http://admin.localhost:3000/admin. Once Finalize initialization succeeds, the admin has zero power over funds.

Steps 1–4: Deploy & Make Immutable

  1. Prepare: Create/unlock vault, generate admin secret key (back it up), connect wallet + DUST, start proof server, collect party keys/ids.
  2. Deploy: Enter buyer/seller role ids, token color, ticker, decimals → Deploy (staged) (6 init circuits, current contract v3). Authority key saved in vault.
  3. Register & Renounce: Register remaining circuits (batches of 4), then Renounce authority (RENOUNCE). Deposit is blocked until renounced.
  4. Initialize: Set attestor/resolver role ids (v3 cash deal: no lender), Unix deadlines (verify local time preview), and KYC policy → Apply.

Steps 5–9: Terms, CASP & Finalize

  1. Private terms: Enter amount (whole tokens), payout keys → Generate package → Commit (configure).
  2. Distribute & back up: Encrypt terms-for-<role>.json per envelope key + download 12+ char passphrase backup. Send attestors an assignment link or sealed notice.
  3. Whitelist CASP: Whitelist active CASP issuer key (required before anyone can accept).
  4. Finalize: Wait for buyer ✓ / seller ✓ at current config version + confirmed backup → Finalize initialization (→ Created).
  5. After finalization: Follow the Contract and Log tabs; back up the vault after each important step.

Buyer guide: Setup, KYC & deposit

Run on http://buyer.localhost:3000/buyer with your own wallet account.

1. Keys, Terms & Acceptance

  • Send 3 public items to Admin: Role id (from /role-id), Shielded payout key (from wallet), Envelope public key (from vault). Never share your secret role key.
  • Import & Accept: Load contract → import role key (buyer) → import terms-for-buyer.json → verify all commitments show match → Accept configuration.
  • Get KYC: Request CASP attestation (e.g. buyer-clean) or import file; pre-checked locally, nothing on-chain yet.

2. 7-Point Deposit Checklist

  1. Status is Created (finalized)
  2. Contract is immutable (authority renounced)
  3. Vault unlocked & buyer role key loaded
  4. Terms imported (all 8 commitments match)
  5. Buyer KYC imported from whitelisted CASP
  6. Sufficient shielded token balance + DUST for fees
  7. Local proof server running on 127.0.0.1:6300
Check that your connected wallet's shielded key matches the committed buyerPayout key before depositing—refunds always go to the committed key.

Seller guide: KYC, review & getting paid

Run on http://seller.localhost:3000/seller with your own wallet account (never the buyer's).

Setup & On-Chain Seller KYC

  • Send Admin your Role id, Shielded payout key (must differ from buyer's), and Envelope public key.
  • Import role key & terms-for-seller.json (verify sellerPayout & amount) → Accept configuration.
  • Seller KYC: Request/import attestation → Submit seller KYC on-chain (validates from Created onward; must not be expired or revoked at release).

Review, Withdrawal & Payout

  • During review: Open contingency review, monitor results, Open dispute, or Withdraw (seller) (refunds buyer).
  • Getting paid (ReadyToClose): Click Release to seller (app verifies KYC & locates vault coin index from deposit tx).
  • Other payouts: Claim forfeited deposit or Claim cooling-off penalty; use Export payout coin if wallet doesn't list it yet.

Inspector, lender, title agent & dispute resolver

Attestors (/inspector, /lender, /title-agent)

  • Must be independent of the seller; 1 result per contingency. Lender attests financing only in a v2 cash deal.
  • Assignment: open the admin's link (Add and open) or Import assignment notice.
  • Submit in ContingenciesPending:
    1. Choose local report file (hashed with random salt; never uploaded).
    2. Pick Favourable or Unfavourable → Submit on-chain.
    3. Export sealed file per named recipient (buyer, seller, notary, resolver, others) or Export for all; recipients check it in Attestor reports.
  • Back up your vault—report salts are stored there.

Dispute Resolver (/resolver)

Acts only in Disputed before the dispute deadline; must import terms-for-resolver.json.

ActionResult
Resolve: settle to sellerSettled (all contingencies must be cleared; only resolver executes release)

Notary portal & compliance officer

Notary Portal (/verify/<address>)

Read-only, no wallet, no fees. Refreshes every 20 seconds.

  • Custodian role: Holds no role key (cannot act). Imports terms-for-custodian.json to back up terms and restore to parties who lost their vault.
  • Openings & reports: Load opening (one private term each), Verify the amounts now as custodian, CASP KYC records, and attestors' report bundles, all checked against on-chain commitments.
  • Checklist before the deed: status, locked funds, price, contingencies, KYC, cooling-off, then the certificate in the same visit.
  • Certificate: Exports EU Notarial Escrow Certificate (V2) as JSON proof bundle or Print/PDF.

Compliance Officer (/compliance)

Talks to CASP via server-side /api/casp/* proxy (tokens stay in .env.local).

  • Inspect KYC (no wallet needed): Verifies CASP connection, whitelisted issuer keys, attestation status, and Travel Rule records.
  • Revocations: Enter kycRef + reason → Request signed revocation (or import file) → Broadcast on-chain (anyone can send; contract checks CASP signature).
  • Effect: Revoked seller KYC or issuer key blocks Release to seller until renewed.

Browser Vault & Backups

  • AES-GCM encrypted in IndexedDB, isolated per browser origin (*.localhost:3000).
  • Back up with a 12+ char passphrase after every step (role key, terms, KYC, report salt).
  • Admin backups hold authority/admin keys; party backups never do.

Restore & Removal

  • Move origin / browser: Use Restore a vault from a backup on the empty vault screen, or Restore (merge) into an existing vault.
  • Remove key (REMOVE): Recoverable from vault history.
  • Erase locally (ERASE): Permanent local deletion—back up first.

Transaction log, DUST fees & troubleshooting

Transaction Log & DUST Fees

  • Tx Log: Tracks local txs (confirmed, failed, interrupted), Import history from chain, and CSV/JSON export (public facts only).
  • DUST Fees: Paid by sender's wallet; generated by NIGHT (up to 5 DUST/NIGHT). Separate from escrow token. Notary & Simulator are free.

Quick FAQ

  • Change amount after accept? Only before finalization (re-configure & both re-accept).
  • Act on behalf of someone? No—every circuit proves the caller's own role key.
  • Redeploy after a contract update? No—supported versions (v3, v2) keep working.
